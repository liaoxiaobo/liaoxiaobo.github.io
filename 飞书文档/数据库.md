### 条件查询\(where、like\)

**统计数学成绩及格的全部学生id**

```SQL
mysql> select stu_id,Math from score where Math>=60;

mysql> select stu_id,Math from score where Math between 60 and 100;
```

**统计语文和数学成绩都大于80分的学生id**

```SQL
mysql> select stu_id,Language,Math from score where Math>80 And Language>80;
```

**查询不是2009年入学的学生姓名和学号**

```SQL
mysql> select name,number from student where number not like '2009%';
```

**查询就读软件专业的学生名字和班级**

```SQL
mysql> select name,class from student where class like '%软件%';
```

### 连接查询

连接查询是另一种类型的多表查询。连接查询对多个表进行JOIN运算，简单地说，就是先确定一个主表作为结果集，然后，把其他表的行有选择性地“连接”在主表结果集上。

**列出数学成绩及格的学生姓名，学号和数学成绩**

```SQL
注意INNER JOIN查询的写法是：

先确定主表，仍然使用FROM <表1>的语法；
再确定需要连接的表，使用INNER JOIN <表2>的语法；
然后确定连接条件，使用ON <条件...>，这里的条件是s.class_id = c.id，表示students表的class_id列与classes表的id列相同的行需要连接；
可选：加上WHERE子句、ORDER BY等子句。

mysql> select name,number,Math from score inner join student on score.stu_id=student.id where Math>=60;
+-----------+--------------+------+
| name      | number       | Math |
+-----------+--------------+------+
| 张三     | 200920205104 |   95 |
| 王五    | 200920205103 |   92 |
| 陈浩      | 200920205201 |  100 |
| 姗姗      | 201303051487 |   76 |
+-----------+--------------+------+
4 rows in set (0.00 sec)
```

### **什么是不可重复读？在什么情况下会出现**

**在一个事务内多次读取同一个数据，如果出现前后两次读到的数据不一样的情况，就意味着发生了「不可重复读」现象。**

事务A第一次读取表数据，此时读取了小明的年龄为20岁，接着事务B执行年龄的更改操作，将小明的年龄更改为30岁，并且已提交事务B成功。此时事务A第二次去读取到小明的年龄时，发现其年龄是30岁，和之前的数据不一样，也就是前后两次读取数据不重复，系统不能读取到重复一致的数据，成为不可重复读。

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=ZDExM2NlYjRlZTc4ZjMyZTE3YzI5NDMyZjVlZDkxYWFfMDFmNmM2MWNjNjMyYTVjZTgzMGQ5OWE5Y2RhZThmYTRfSUQ6NzY0NjMwNjM1MzY5MDUxMjMxNl8xNzgxMzY5MDc2OjE3ODE0NTU0NzZfVjM)

不可重复读是事务A读取到了其它事务执行update后的数据，**可以使用行级锁，锁定该行**，事务A多次读取操作完成后才释放该锁，此时才允许其它事务操作数据。

### **什么是幻读？在什么情况下会出现**

**在一个事务内多次进行查询某个符合查询条件的「记录数量」，如果出现前后两次查询到的记录数量不一样的情况，就意味着发生了「幻读」现象。**

事务A在执行读取操作，需要两次统计数据的总量，前一次查询数据总量后，此时事务B执行了新增数据的操作并提交后，这个时候事务A读取的数据总量和之前统计的不一样，就像产生了幻觉一样，平白无故的多了几条数据，成为幻读。

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=NzQzNjg0ZjA4ZjhjMzdiZWI0M2ZmNzc5YWUzMjkxYWZfZjdiY2JiODRiNWVmODNmNTUzYTNjOGJhMDZhZDE2NDlfSUQ6NzY0NjMwNjM1MzMwMDM3NjUzN18xNzgxMzY5MDc2OjE3ODE0NTU0NzZfVjM)

幻读是事务A读取了其它事务执行insert或delete后的数据，**可以使用表级锁，锁定整张表**，事务A多次读取数据总量之后才释放该锁，此时才允许其它事务操作数据。

### 什么是悲观锁，有什么作用？

悲观锁就是在操作数据时，认定此操作会出现数据冲突，所以在进行每次操作时都要通过获取锁才能进行对相同数据的操作。**共享锁**（读锁）和**排它锁**（写锁）都属于悲观锁。



事务A手动加了**共享锁，**其他事务可以并发读取数据，但不能对相同数据进行修改，否则会造成锁等待超时或死锁。加上共享锁后，对于update，insert，delete语句会自动加排它锁。

### 死锁问题解决

死锁解决方式：

1、数据库引擎（innodb）实现各种死锁检测和死锁超时机制。比如将持有最少行数的排他锁的事务做回滚

2、查询时间达到锁等待超时设定后放弃锁请求。

第一种：

1. 查询是否锁表 show OPEN TABLES where In\_use \> 0;

2. 查询进程 show processlist

3. 杀死进程id（就是上面命令的id列）kill id

第二种：

1. 查看当前的事务 SELECT \* FROM INFORMATION\_SCHEMA\.INNODB\_TRX;

2. 查看当前锁定的事务 SELECT \* FROM INFORMATION\_SCHEMA\.INNODB\_LOCKS;

3. 查看当前等锁的事务 SELECT \* FROM INFORMATION\_SCHEMA\.INNODB\_LOCK\_WAITS;
