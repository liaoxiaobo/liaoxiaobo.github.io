# stress

stress是一个linux的压力测试工具，专门用于对设备的CPU、IO、内存、负载、磁盘等进行压测。

## 工具安装

**方法一：yum安装\(适用于centos\)**

```YAML
yum install -y epel-release
yum install -y stress


```

注意：如果遇到下载不了包的问题，就需要先替换下yum源。

**方法二：下载包安装**

访问网址 [https://fossies\.org/](https://fossies.org/)，搜索stress工具包进行下载

```Bash
wget https://fossies.org/linux/privat/old/stress-1.0.4.tar.gz
cd stress-1.0.4
./configure
make
make check
make install
make clean


```

安装过程中，\./configure若遇到以下错误，执行以下命令后即可解决。

```Bash
yum install gcc -y


```

**方法三：容器镜像安装**

```Bash
docker run -d polinux/stress sleep 100000


```

## 基本语法

```Bash
Usage: stress [OPTION [ARG]] ...
 -?, --help         show this help statement
     --version      show version statement
 -v, --verbose      be verbose
 -q, --quiet        be quiet
 -n, --dry-run      show what would have been done
 -t, --timeout N    timeout after N seconds
     --backoff N    wait factor of N microseconds before work starts
 -c, --cpu N        spawn N workers spinning on sqrt()
 -i, --io N         spawn N workers spinning on sync()
 -m, --vm N         spawn N workers spinning on malloc()/free()
     --vm-bytes B   malloc B bytes per vm worker (default is 256MB)
     --vm-stride B  touch a byte every B bytes (default is 4096)
     --vm-hang N    sleep N secs before free (default none, 0 is inf)
     --vm-keep      redirty memory instead of freeing and reallocating
 -d, --hdd N        spawn N workers spinning on write()/unlink()
     --hdd-bytes B  write B bytes per hdd worker (default is 1GB)

Example: stress --cpu 8 --io 4 --vm 2 --vm-bytes 128M --timeout 10s

Note: Numbers may be suffixed with s,m,h,d,y (time) or B,K,M,G (size).


-? 显示帮助信息
-v 显示版本号
-q 不显示运行信息
-n 显示已完成的指令情况
-t --timeout N 指定运行N秒后停止
--backoff N 等待N微妙后开始运行
-c 产生n个进程 每个进程都反复不停的计算随机数的平方根
-i 产生n个进程 每个进程反复调用sync()，sync()用于将内存上的内容写到硬盘上
-m --vm n 产生n个进程,每个进程不断调用内存分配malloc和内存释放free函数
--vm-bytes B 指定malloc时内存的字节数 （默认256MB）
--vm-hang N 指定在free前的秒数
-d --hdd n 产生n个执行write和unlink函数的进程
-hdd-bytes B 指定写的字节数
时间单位可以为秒s，分m，小时h，天d，年y，文件大小单位可以为K，M，G


```

### 内存压力测试

使用 `stress -m N` 会让stress生成N个工作进程来占用内存。每个进程默认占用256M内存，但可以通过 `--vm-bytes` 来进行设置。

虽然只是对内存进行压力测试，但实际上CPU也是很繁忙的，占有率也接近100%。这是因为

默认在不断释放并重新分配内存，user 非常高\(cpu 在用户态忙碌\)。

\*\*\-\-vm\-keep：\*\*一直占用内存，默认是不断释放并重新分配内存。

例如新增4个内存分配进程，每次分配大小1G，分配后不释放，测试100s

`stress -m 4 --vm-bytes 1G --vm-keep -t 100s`

iPerf 是专业的网络测试工具，它基于 TCP/IP 和 UDP/IP 协议，用以测量两个网络节点之间 TCP 和 UDP 端口的网络带宽，还能提供网络延迟、丢包率等统计信息。

iPerf 常用的版本有 iPerf2 和 iPerf3。 iPerf3 在 iPerf2 的基础上新增了一些功能，例如发送方/接收方角色互换，以 JSON 格式输出结果，零拷贝方式传输数据等等。也去掉了 iPerf2 中所支持少许功能，例如双向测试，以逗号为分隔符输出结果等。iPerf3 和 iPerf2 所执行的命令名字也不一样，iPerf3 为 iperf3，iPerf2 为 iperf。下文中的测试都以 iPerf3 为例。

## 基本语法

iPerf 在工作时，测试的两端一方作为 Server，另一方为 Client。程序启动的命令相同，通过不同的参数来区别以哪种工作方式运行。通常情况下先启动 Server 端，使 iPerf 监听在某个固定端口。然后在 Client 端执行相应的命令开始测试。

以下是 iPerf 3\.1\.2 支持的所有参数：


## Nginx配置负载均衡

**配置示例**

```Bash
user  nginx;    # 配置用户或者组，默认为nobody nobody
worker_processes  1;  # Nginx开启的worker进程数，建议为CPU的核数

error_log  /var/log/nginx/error.log;
pid        /var/run/nginx.pid;


events {
    worker_connections  1024; # 最大连接数，默认为512
}


http {
    include       /etc/nginx/mime.types;    # 文件扩展名与文件类型映射表
    default_type  application/octet-stream; # 默认文件类型，默认为text/plain

    log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                      '$status $body_bytes_sent "$http_referer" '
                      '"$http_user_agent" "$http_x_forwarded_for"';

    access_log  /var/log/nginx/access.log  main; # 服务日志

    sendfile        on; # 高效文件传输
    tcp_nopush     on; # 需sendfile开启，防止网路阻塞，将响应头和正文一起发送，减少网络报文数量

    keepalive_timeout  60; 连接超时时间，可以在http，server，location块
    gzip              on; # 开启gzip资源压缩
    
    #include /etc/nginx/conf.d/*.conf; # 可以在任意地方使用include指令实现配置文件的包含

    # 负载均衡配置
    upstream prometheus_server{
        server 139.198.126.114:32001 weight=1;
        server 139.198.125.209:32001 weight=1;
        server 139.198.125.199:32001 weight=1;
    }

    upstream alert_server{
        server 139.198.126.114:32003  weight=1;
 }
 
     client_header_buffer_size    128k;  # 设定请求缓冲  
     large_client_header_buffers  4 128k;  # 设定请求缓冲   
     client_max_body_size 8m; # 上传文件的大小限制，默认1m


    server {
        listen       80;    # 监听端口
        server_name  static.web.com;    # 监听地址
        proxy_headers_hash_max_size     51200;
        proxy_headers_hash_bucket_size  6400;
        # 将$remote_addr的值放进变量X-Real-IP中，$remote_addr的值为客户端的ip
        proxy_set_header                X-Real-IP        $remote_addr;
        # 客户端通过nginx访问后端服务, 后端服务通过该变量会记录真实客户端地址
        proxy_set_header                X-Forwarded-For  $proxy_add_x_forwarded_for;

        #location / {
        #    root /usr/share/nginx/html;
        #    index index.html;
        #}
        location / {
            proxy_pass  http://prometheus_server/; # 请求转向prometheus_server定义的服务器列表 
            proxy_connect_timeout     50s;
            proxy_read_timeout  60s；
            proxy_send_timeout 60s;
            proxy_set_header Host      $host    # 定义nginx向后端传递的请求里携带真实的请求头host值
        }
        location /alert/ {
            proxy_pass  http://alert_server/;
            proxy_connect_timeout     30s;
        }
    }
}


```

### nginx 获取客户端真实IP

如果使用了反向代理或者负载均衡器，那么程序中需要使用 `X-Forwarded-For` 变量来获得真实的客户端IP地址。

- `**X-Forwarded-For**`，用来记录代理服务器的地址，每经过一层代理都会追加一个记录。格式为`client ip，proxy ip1，proxy ip2`

- `**X-Real-IP**`，同样用来记录代理服务器的地址，但是和上面的不同它不把记录追加到尾部，而是直接替换掉。

- `**Host**`，为后端服务器重新设定Host主机头，`$host`变量的值在请求包含"Host"请求头时为"Host"字段的值，在请求未携带"Host"请求头时为虚拟主机的主域名。

- `**remote_addr**`，表示客户端地址，注意如果存在nginx代理服务器，则是nginx服务器的ip地址

- `**proxy_pass**`，经过调整头部信息后，将请求转发到后端的服务器。

```Python

server{

    #... 其它配置项省略

    location ^~ /static {
        alias /django-demo/static/;
        expires 30d;
    }

    location / {
        proxy_set_header X-Real-IP $remote_addr; # 将X-Real-IP赋值给remote_addr
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; # 如果存在多层代理，需设置该项
        proxy_set_header Host $host;

        proxy_pass http://unix:/var/run/django.socket;
        #proxy_pass http://upstream_server:8000;
    }

    #... 其它配置项省略

}


```

### location 模块常用参数

- proxy\_connect\_timeout：nginx与upstream server建立连接的超时时间，一般不超过75s ；若超过会出现 504 Gateway timeout 错误

- proxy\_read\_timeout：连接成功后，它决定了nginx会等待多长时间来获得请求的响应

- proxy\_send\_timeout：这个指定设置了发送请求给upstream服务器的超时时间。超时设置不是为了整个发送期间，而是在两次write操作期间。如果超时后，upstream没有收到新的数据，nginx会关闭连接

### upstream 模块常用参数

- weight：指定服务器的权重，默认值为1；基于weight可实现轮询、加权轮询两种负载均衡算法

- max\_conns：限制代理服务器到上游服务器的最大连接数量，默认值0，代表不限制

- least\_conn: 负载均衡的算法之一，该算法会将户端的请求分配到活动连接数最少的上游服务器

- ip\_hash：负载均衡算法的一种，该算法确保来自于同一客户端ip的请求始终传递到同一台服务器（有利于保持session）

- sticky：主要用于会话保持

- down：该参数将服务器标记为永久不可用

- backup：该参数将上游服务器标记为备用，当有其它服务器故障时，该备用服务器被自动启用

- keepalive：该参数定义Nginx与上游服务器之间保留在每个辅助进程的缓存的空闲连接数

## Nginx**实现会话保持**

### ip\_hash

ip\_hash使用源地址哈希算法，每个请求按访问ip的hash算法结果分配，这样每个访客固定访问一个后端服务器，从而实现了会话保持，除非该服务器不可用。ip\_hash不适用于CDN网络，不适用于前段还有代理的情况。

**配置示例**

```Python
upstream bakend {
    ip_hash;
    server 192.168.0.11:80;
    server 192.168.0.12:80;
}


```

### sticky

sticky是一个第三方模块（nginx\-sticky\-module）提供的功能，利用cookie实现会话保持。

在 cookie insert模式下，nginx 将负责插入 cookie ，后端服务器无需作出任何修改。当客户端进行第一次请求时，后端服务器的响应回复在经过nginx时，会被nginx插入一个cookie标识，该标识会与后端服务器做唯一的映射。在有效期内，当客户端携带该cookie第二次向nginx发起请求时，nginx会把该请求根据cookie标识，转发至同一台后端服务器。

```Python
# sticky语法
sticky [cookie=name] [domain=your_domain] [path=your_path] [maxage=time] [mode=insert|rewrite|prefix] [option=indirect] [maxidle=time] [maxlife=time] [fallback=on|off] [hash=sha1|md5|index]

# 默认配置
sticky cookie=route mode=insert fallback=on

# 参数说明
cookie: 设置用来记录会话的cookie名称
domain: 设置cookie作用的域名，默认不设置
path: 设置cookie作用的URL路径，默认不设置
expires：设置浏览器中保持cookie的时间
maxage: 设置cookie的生存期，默认不设置，即为session cookie，浏览器关闭即失效
mode: 设置cookie的模式
insert: 在回复中本模块通过Set-Cookie头直接插入相应名称的cookie。
prefix: 不会生成新的cookie，但会在服务器响应的cookie值前面加上特定的前缀，当浏览器带着这个有特定标识的cookie再次请求时，模块在传给后端服务前先删除加入的前缀，后端服务拿到的还是原来的cookie值，这些动作对后端透明。如：”Cookie: NAME=SRV~VALUE”。
rewrite: 使用服务端标识覆盖后端设置的用于session sticky的cookie。如果后端服务在响应头中没有设置该cookie，则认为该请求不需要进行session sticky，使用这种模式，后端服务可以控制哪些请求需要sesstion sticky，哪些请求不需要。
option: 设置用于session sticky的cookie的选项，可设置成indirect或direct。indirect不会将session sticky的cookie传送给后端服务，该cookie对后端应用完全透明。direct则与indirect相反。
maxidle: 设置session cookie的最长空闲的超时时间
maxlife: 设置session cookie的最长生存期
fallback: 设置是否重试其他机器，当sticky的后端机器挂了以后，是否需要尝试其他机器
hash: 设置cookie中server标识是用明文还是使用md5值，默认使用md5


```

## Nginx**实现健康检查**

nginx原生提供的health\_check机制其实很薄弱，做不到主动探测，属于被动式的健康检查。主要是通过在upstream中配置max\_fails和fail\_timeout来实现。

fail\_timeout：设定server被认为不可用的时间段，超过该值，请求还是会转发至该server

max\_fails：在fail\_timeout时间段内，如果失败次数达到此值，server被认定为不可用。

```Python
upstream backend {
    server localhost:9090 max_fails=1 fail_timeout=40s;
    server localhost:9191 max_fails=1 fail_timeout=40s;
}


```

### nginx\_upstream\_check\_module

`nginx_upstream_check_module`为淘宝技术团队开发的nginx模块，用来主动检测后方server的健康状态，如果后端服务器不可用，则请求不再转发到这台服务器。

**配置示例**

```Python
upstream 1dbfdfc9-a3e7-452d-9a5e-f39ed88f6e1d{

         server 192.168.100.5:80 weight=1;
         server 192.168.100.10:80 weight=1;
         
     check interval=3000 rise=2 fall=5 timeout=1000 default_down=true type=http;
     check_http_send "HEAD / HTTP/1.0\r\n\r\n";
     check_http_expect_alive http_2xx http_3xx;

}


```

- interval： 检测间隔3秒

- fall: 连续检测失败次数5次时，认定server is down

- rise: 连续检测成功2次时，认定server is up

- timeout: 超时1秒

- default\_down: 初始状态为down,只有检测通过后才为up

- type: 检测类型方式tcp :tcp 套接字,不建议使用，后端业务未100%启动完成,前端已经放开访问的情况ssl\_hello： 发送hello报文并接收relaserver 返回的hello报文http: 自定义发送一个请求，判断上游relaserver 接收并处理mysql: 连接到mysql服务器，判断上游relaserver是否还存在ajp: 发送AJP Cping数据包，接收并解析AJP Cpong响应以诊断上游relaserver是否还存活\(AJP tomcat内置的一种协议\)fastcgi: php程序是否存活

### 连接查询

连接查询是另一种类型的多表查询。连接查询对多个表进行JOIN运算，简单地说，就是先确定一个主表作为结果集，然后，把其他表的行有选择性地“连接”在主表结果集上。

**列出数学成绩及格的学生姓名，学号和数学成绩**

```SQL
注意INNER JOIN查询的写法是：

先确定主表，仍然使用FROM <表1>的语法；
再确定需要连接的表，使用INNER JOIN <表2>的语法；
然后确定连接条件，使用ON <条件...>，这里的条件是s.class_id = c.id，表示students表的class_id列与classes表的id列相同的行需要连接；
可选：加上WHERE子句、ORDER BY等子句。

mysql> select name,number,Math from score inner join student on score.stu_id=student.id where Math>=60;
```

```Bash

ERROR 1786 (HY000): Statement violates GTID consistency: CREATE TABLE ... SELECT.
```

当前数据库实例中开启了 GTID 功能, 在开启有 GTID 功能的数据库实例中, 导出其中任何一个库, 如果没有显示地指定–set\-gtid\-purged参数, 都会提示这一行信息\. 意思是默认情况下, 导出的库中含有 GTID 信息, 如果不想导出包含有 GTID 信息的数据库,需要显示地添加–set\-gtid\-purged=OFF参数\.

```Bash
# 加上--set-gtid-purged=OFF参数
root@Master:/# mysqldump -uwise2c -p --set-gtid-purged=OFF bldr user > user_bak.sql
Enter password:
root@Master:/# ls user*
user_bak.sql
```
