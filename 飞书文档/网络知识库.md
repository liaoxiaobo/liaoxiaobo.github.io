# 虚拟私有云 VPC

**VPC**（Virtual Private Cloud）是云平台上自定义的**逻辑隔离**网络空间，不同的私有网络之间二层逻辑隔离。用户可以自定义**IP地址段、路由策略**等，并通过**安全组**和**网络 ACL**等实现多层安全防护。

## 基本概念

**端口**

端口定义了 MAC 地址和 IP 地址，每个端口都有一个唯一的标识符（tap设备ID）。当虚拟网卡 VIF（Virtual Interface） 绑定到端口时，端口会将 MAC 和 IP 分配给虚拟网卡。

**路由表**

决定VPC网络中数据包的转发路径。它定义了VPC中不同子网之间的通信规则。默认情况下，**同一VPC内的子网默认互通。**

**虚拟IP**

虚拟IP是一种可以独立创建和释放的私网IP资源，可以与高可用软件（例如[Keepalived](https://keepalived.readthedocs.io/en/latest/introduction.html)）配合使用，实现多服务器架构下的VIP漂移，确保对外提供服务的私网IP不变，提高业务的高可用性。

**安全组**

虚机（端口）级别的防火墙，用于控制安全组内实例的入流量和出流量，从而提高ECS实例的安全性。

**网络ACL**

子网级别的无状态防火墙，默认规则通常**允许所有入站和出站流量**

## VPC实现原理

VPC通常使用Overlay 技术（如 VXLAN、Geneve）构建虚拟二层网络，实现资源逻辑隔离。

Geneve 可增强 VPC 能力：

- 通过 TLV 元数据支持动态策略（如安全组规则、服务链配置），提升 VPC 的灵活性和安全性

- 在跨 VPC 或混合云场景中，Geneve 可携带 VPC 标识、流量方向等元数据，简化路由控制

## VPC网络类型

根据VPC网络的类型，可以分为

• Flat network：基于不使用 VLAN的物理网络实现的虚拟网络。每个物理网络最多只能实现一个虚拟网络。

• VLAN network（虚拟局域网）：基于物理VLAN网络实现的虚拟网络。共享同一个物理网络的多个 VLAN 网络是相互隔离的，甚至可以使用重叠的 IP 地址空间。有效的 VLAN ID 范围是 1 到 4094。

• VXLAN network（虚拟可扩展网络）：基于VXLAN实现的虚拟网络。

• Geneve（Generic Network Virtualization Encapsulation）与VxLAN类似也使用了UDP进行封装，也有24比特的网段级别，但是它在报文中增加了一个可选字段（Option），允许虚拟化应用实现扩展。目前该类型网络在裸机高速网络场景下使用，用于区分低速裸机网络。

**VXLAN vs\. GENEVE**

从表面来看，VXLAN 和 Geneve 提供的功能相同，都是在三层 IP 数据包内封装和传输二层帧。两者都使用 UDP 协议来实现其功能。然而，两种隧道协议还是有较大的区别。VXLAN 帧的标头长度是 8 字节，而 Geneve 的标头长度是 16 字节。此外，VXLAN不具备传输安全、服务链和带内遥测。Geneve 解决了 VXLAN 的一些主要缺点：

- VXLAN缺少协议标识符字段。VXLAN进一步的多路复用/多路分解需要在负载地址中提供协议标识符，而 VXLAN 缺少该协议标识符。

- VXLAN不能发送不属于客户端的包帧，即对方无法区分是否是客户端包。

- VXLAN 中的所有字段都是固定的，无法通过使用可扩展字段实现互操作性，GENEVE 的最大特点是拥有灵活的可变长区域，提供了更为灵活的空间。

## 安全组与防火墙的区别

从流量的角度再来看下，访问VPC内部虚拟机的流量到公有网络后，先经过VPC路由器，也就是防火墙，然后是VPC网络，再到虚拟机端口上，经过安全组过滤最后发给虚拟机。

**防火墙主要是做南北向的访问控制，作用范围是整个VPC（子网网关），安全组主要是做东西向的访问控制，作用范围是虚拟机网卡，和防火墙形成互补的关系。**

3. 虚机内的路由规则说明：

`**default via 192.168.99.1 dev eth0 proto dhcp metric 100**`

- **作用**：这是默认路由（兜底规则），表示**所有不匹配其他规则的流量**都会通过这个路径发送。

- **细节**：

    - `default`：代表所有未明确指定目标的流量（例如访问互联网的公网地址）。

    - `via 192.168.99.1`：流量会被发送到网关 `192.168.99.1`（通常是路由器或云环境的虚拟网关）。

    - `dev eth0`：使用网卡 `eth0` 发送流量。

    - `proto dhcp`：这条路由是通过 DHCP 自动获取的（云服务器一般自动配置）。

    - `metric 100`：路由优先级为 100（数值越小优先级越高，这里没有冲突）。

- **实际场景**：

当你访问百度（公网 IP）时，流量会走这条规则，通过网关 `192.168.99.1` 出去

`**169.254.169.254 via 192.168.99.12 dev eth0 proto dhcp metric 100**`

- **作用**：专门处理目标地址 `169.254.169.254` 的流量（云服务商的元数据服务器）。

- **实际场景**：

当你在实例内通过 `curl http://169.254.169.254` 获取实例的元数据（如内网 IP、密钥等）时，流量直接通过本机网卡发送，不经过网关。

`**192.168.99.0/24 dev eth0 proto kernel scope link src 192.168.99.12 metric 100**`

- **作用**：处理本地子网内的通信（即同一子网 `192.168.99.0/24` 的流量）。

- **细节**：

    - `192.168.99.0/24`：表示目标地址在 `192.168.99.0` 到 `192.168.99.255` 范围内的流量。

    - `dev eth0`：直接通过网卡 `eth0` 发送（无需经过网关）。

    - `proto kernel`：这条路由是内核自动生成的（根据网卡配置）。

    - `src 192.168.99.12`：发送数据包时，源 IP 使用 `192.168.99.12`（本机私有 IP）。

- **实际场景**：

当你访问同一子网内的其他服务器（如 `192.168.99.20`）时，流量直接通过网卡 `eth0` 发送，不经过网关。

Flags标志说明：

- U Up表示此路由当前为启动状态

- H Host，表示此网关为一主机

- G Gateway，表示此网关为一路由器

- R Reinstate Route，使用动态路由重新初始化的路由

- D Dynamically，此路由是动态性地写入

- M Modified，此路由是由路由守护程序或导向器动态修改

- \! 表示此路由当前为关闭状态

# 云内互通（东西向流量）

## 同vpc互访：子网内二层转发

**子网内虚机通信（经过mac）直接走二层，数据包不会经过路由器（子网网关）转发。**

子网内互ping fixip（liaoxb02 ping liaoxb01） ，并在liaoxb01虚机上抓包`tcpdump -nnei eth0 icmp`。在目的虚机内抓包，**可以发现数据包的源mac、源ip就是虚机liaoxb02的mac和ip地址**

## 跨vpc互访：对等连接 PC

VPC是私有隔离的网络，用户可以通过对等连接功能实现同一个区域内，不同VPC之间的云上内网通信。

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=ODI1ZGQzNTAzYTI1ZGQ3Y2MxZjdjMjM0ZTk5OTdmYWZfNmRiMTc3MDkwOTZiMGJiOWU2MjE3YTFhZjJhZTg4NzJfSUQ6NzY0ODE5OTA0Mjk0NTg5NTY2MF8xNzgxMzY5MjE5OjE3ODE0NTU2MTlfVjM)

**主要特性**

- 更高质量

业务共享同一自建内部网络，不受公网质量影响，与同一VPC内的网络性能几乎相同，可用性、时延、丢包率保障大大提高。

- 更强安全性

可以安全的打通VPC之间的流量通道，不经过广域 Internet 和运营商链路，避免报文在公网传输可能被窃取的风险。

- 更加便捷

可连接不同租户或相同租户下的VPC流量通道（跨租户建立连接需要授权码，即jwt token）

- 更加灵活

对等连接的工作粒度是子网，即用户可以选择打通VPC之间的部分子网的流量

## 跨vpc互访：企业路由器 ER

企业路由器可以实现多VPC、DC、跨区域ER互联，在接入的所有网络实例之间路由流量，可以简化网络拓扑，降低网络管理难度，提升网络运维效率。

**主要特性**

- 对于VPC互通，不再需要频繁创建多个VPC对等连接，维护每个VPC路由表。

- 对于VPC和专线/VPN互通，不用接入多条专线，多个VPC可以共享专线/VPN。

- 企业路由器支持路由学习，能够自动进行路由信息的更新和同步，当网络拓扑变更时，能够自动收敛，无需手工配置、变更繁琐的路由条目。

## 弹性公网IP

公网IP可以与云服务器、裸金属服务器、虚拟IP、弹性负载均衡、NAT网关等资源灵活地绑定及解绑，实现资源访问公网（SNAT）和被公网访问（DNAT）的需求，使各资源独立对外提供服务。

## 负载均衡 ELB

弹性负载均衡（ELB）可以将访问流量自动分发到同一组ECS实例（只支持DNAT）。消除应用系统的单点故障提高可靠性，还可以扩展应用系统对外服务的能力提升可用性。

**服务特性**

负载均衡服务实现了安全、稳定、可弹性扩展的多云主机流量分发，提升应用系统对外的服务能力

- 同一个SLB支持多个监听器，通过不同监听器对外提供多种服务。

- 同一个监听器支持多个资源池，通过不同资源池进行流量的负载均衡。

- 支持多种负载均衡算法，如加权轮询、轮询、最少连接数、源IP。

- 支持多种健康检查，自动摘除故障。

- 支持SSL单双向认证以及SNI，并支持国密证书。

## NAT网关

NAT网关是为虚拟私有云提供网络地址转换的服务，提供源地址转换（SNAT）和目的地址（DNAT）转换两种能力。

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=Mjc3MjE1YTczNDlmNTIxZTBjMWZjOWE5ODQyZGE2YTFfY2MwOTAxNjEyNzFjOGFjMWI1Mjg4NjRiMDg3OWU0NTRfSUQ6NzY0ODE5OTA0MTk3Mjg2NjI3Ml8xNzgxMzY5MjE5OjE3ODE0NTU2MTlfVjM)

提供SNAT和DNAT两种功能：

9. SNAT可实现VPC内的多个ECS共享使用EIP，有效降低管理成本，同时减少了ECS的EIP直接暴露的风险。

10. DNAT功能可以实现端口级别的转发，将EIP的端口映射到不同ECS的端口上，使VPC内多个ECS共享同一EIP和带宽面向公网提供服务，但没有均衡流量的功能。

### 总结

**vpc内的虚机通信：**

同一计算节点的虚机，数据包直接走**br\-int**网络（包含所有虚机的tap设备信息）

跨计算节点的虚机，数据包需要走本端计算节点上的**geneve**隧道网络（100\.125\.254\.x），封包后会转发到远端计算节点后解包

虚机内的数据包走默认路由时，分以下几种情况

1、目的地址如果是mfip，数据包的源mac会经过snat转换成计算节点的mac地址，源IP会转换为虚机mfip

2、目的地址如果是eip，数据包源mac会经过snat转换成计算节点的mac地址，源IP会转换为虚机eip
