# 2 测试开发基础能力

## 定位

支撑测试开发的通用技术栈。这个领域存放不绑定具体框架、不绑定具体业务项目的底层能力，是阅读后续自动化测试、云原生测试、专项测试等内容的先修知识。

## 设计原则

1. **测试开发视角**：每篇文档都要说明"这个知识点在测试工作中怎么用"，避免变成通用技术教程。
2. **与 3/4/5 域解耦**：这里只放通用基础能力，框架用法进 `3 自动化测试工程`，基础设施进 `4 云原生与基础设施测试`，专项测试进 `5 专项测试技术`。
3. **语言级 vs 框架级分离**：例如 Python 的 `unittest.mock` 属于语言级能力，放 2.1.2；Pytest 的 `fixture`/`parametrize` 属于框架级能力，放 3.1.1。

## 落地优先级

按"高频使用 + 源文档成熟"排序：

- **P0（优先整理）**：2.2 Linux 基础、2.3 计算机网络、2.6 Git
  - 源文档成熟，整理工作量小，日常查询频率高。
- **P1（次优先）**：2.1 Python 测试编程、2.4 数据库基础
  - 源文档体量大，但需要补充测试视角，整理工作量中等。
- **P2（可后延）**：2.5 数据结构与算法、2.7 AI 编程工具
  - 2.5 需要重新提炼与测试工作的关联；2.7 依赖实际使用经验积累。

## 关键边界提醒

- **2.1.2 vs 3.1.1 Pytest**：2.1.2 讲 Python 语言级能力（mock、解析、并发），3.1.1 讲 Pytest 框架级能力（fixture、parametrize、插件）。
- **2.4.2 vs 4.10 AI 辅助测试数据生成**：传统造数方法放 2.4.2，LLM 生成测试数据放 4.10。
