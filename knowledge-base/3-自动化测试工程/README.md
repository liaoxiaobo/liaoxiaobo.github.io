# 3 自动化测试工程

## 定位

知识库核心支柱之一，覆盖测试框架、UI 自动化、接口自动化、CI/CD 集成、AI 辅助测试开发。聚焦"如何把自动化测试真正落地到项目里"，既讲框架怎么用，也讲框架怎么设计、怎么度量、怎么持续演进。

## 设计原则

1. **框架级与语言级分离**：Pytest 的 `fixture` / `parametrize` / 插件机制放 3.1.1；Python 的 `unittest.mock` / 装饰器 / 并发控制放 2.1.2。
2. **通用方法与项目案例分离**：同一主题只保留一份通用方法论，项目细节通过 `#项目` 标签和项目索引页横向串联，不在不同目录重复存放。
3. **工具教程与架构设计分离**：工具入门（如 Playwright API 速查）放 3.2.1，框架设计思想和评判标准放 3.2.5，最佳实践与复盘放 3.2.6。
4. **AI 能力场景化落地**：AI 不是独立目录，而是按场景拆入 3.5（接口/UI 辅助、脚本自愈）等节点。
5. **每篇文档必须回答**：这个能力对测试开发有什么用？测试切入点在哪里？有哪些可复用的脚本/配置/Checklist？

## 落地优先级

按"价值高 + 源文档成熟 + 与当前工作关联强"排序：

- **P0（优先整理）**：3.1.1 Pytest、3.2.1 Playwright 实践、3.2.5 UI 自动化框架设计、3.2.6 UI 自动化最佳实践与复盘
  - 源文档成熟，与 Sugon Cloud Web 自动化项目直接相关，是简历核心素材。
- **P1（次优先）**：3.4.1 Jenkins Pipeline、3.5.3 LLM 脚本自愈与自动修复
  - 高价值但需拆分项目细节，或依赖 AI 经验积累。
- **P2（可后延）**：3.1.2 Robot Framework、3.2.2 Selenium 实践、3.2.3 POM、3.3.1 接口自动化测试、3.4.2 Docker 化测试执行、3.5.1 / 3.5.2 AI 辅助接口/UI 测试
  - 源文档较少或偏工具入门，可在 P0/P1 成稿后补充。

## 关键边界提醒

- **3.1.1 Pytest vs 2.1.2 Python 测试编程实践**：3.1.1 讲 Pytest 框架专属能力（fixture、parametrize、hook、插件），2.1.2 讲 Python 语言级能力（mock、解析、并发、装饰器）。
- **3.2.5 UI 自动化框架设计 vs 3.2.6 UI 自动化最佳实践与复盘**：3.2.5 讲"怎么设计框架"，3.2.6 讲"怎么评判和优化框架"。
- **3.5.3 LLM 脚本自愈 vs 6.2.2 AI 智能失败归因**：3.5.3 聚焦脚本自动修复，6.2.2 聚焦失败根因分析与分类，两者可互相链接但定位不同。
